# Gemini 抗截断（SillyTavern 独立扩展）

版本：0.1.0。适配与本地验收基准：SillyTavern 1.19.0，提交 `06bde939fb1e9c4c8d8641d810f0a916b5bce127`。

借鉴 RP-Hub 的 `output_reply` 方法：让 Gemini 在工具参数中提交回复，扩展将其还原为普通助手正文。中文、换行、表情、Markdown 和面板标记会继续经过酒馆原有的显示、正则、保存和候选回复流程。

这是独立扩展，不需要记忆插件、酒馆助手、Extras 或服务器插件。模型请求仍走酒馆原有后端，扩展不保存 API 密钥。真实 Gemini 的抗截断效果尚未做对照实验，不能保证消除截断。

## 安装

### 通过酒馆安装

1. 打开酒馆的“扩展程序 → 安装扩展程序”。
2. 填入仓库地址：`https://github.com/ShirahaTobisa/ST-Gemini-Reply`。
3. 安装后刷新页面，在“扩展程序 → Gemini 抗截断”中勾选“启用 Gemini 抗截断”。默认关闭。
4. 连接支持函数工具调用的 Gemini 模型，正常发送聊天。开关从下一次请求生效。

### 手动安装 ZIP

原始离线验收包在 [release 目录](https://github.com/ShirahaTobisa/ST-Gemini-Reply/tree/main/release)，附 SHA-256 校验值。它保留首次打包时的文档；仓库版补充了 GitHub 安装说明，运行代码相同。

1. 将安装 ZIP 解压，得到 `ST-Gemini-Reply` 文件夹。
2. 放到酒馆的 `public/scripts/extensions/third-party/` 下。最终应存在 `public/scripts/extensions/third-party/ST-Gemini-Reply/manifest.json`，不要多套一层目录。
3. 刷新酒馆页面。在“扩展程序 → Gemini 抗截断”中勾选“启用 Gemini 抗截断”。默认关闭。
4. 连接支持函数工具调用的 Gemini 模型，正常发送聊天。开关从下一次请求生效。

安装本扩展不需要执行 npm install，也不用修改酒馆核心文件。“安装扩展程序”网址框使用上面的仓库地址；ZIP 用于手动解压安装。

## 支持范围

| 场景 | 行为 |
|---|---|
| Google AI Studio / Vertex AI | 适配原生 Gemini 响应；经本地酒馆后端与模拟接口验证 |
| 自定义 OpenAI 兼容接口 | 经本地酒馆界面与模拟接口验证 |
| OpenRouter / OpenAI 来源中的 Gemini 模型 | 使用兼容格式转换；未做真实服务联测 |
| 正常聊天、重生成、候选、手动续写 | 接管本次 Gemini 请求，正文由酒馆保存 |
| 关闭流式显示 | 完成后一次显示；原生 Gemini 在内部仍按流读取，以保留结束原因 |
| 普通文本兜底 | 保留正文，明确提示本次接口未使用正文工具 |
| 真正空回复 | 最多总共 3 次请求；推理、工具、格式错误、拒绝、HTTP 错误或取消不会触发这条重试 |
| 长度上限、缺少结束标记、参数未闭合、断流 | 保留可解码正文，标记未完成 |
| 用户取消 | 停止本次请求，保留酒馆已显示的文字和取消状态 |

仅识别名称包含 `gemini` 的模型。模型别名不包含该字符串时会跳过。浏览器需支持酒馆 1.19 所用的现代 JavaScript、流式读取及 `crypto.randomUUID()`；非本机站点请按酒馆正常 HTTPS 方式访问。

以下情况显示“本轮未启用”并保留原请求：非 Gemini、后台静默生成、AI 帮答、结构化输出、原生联网搜索、图片生成、一次生成多个候选、明确禁止或指定其他工具、已有同名 `output_reply`、自定义请求体覆盖，以及未适配的来源。

其他函数工具仍由酒馆处理。若本次已经指定必须先调用某个工具，扩展跳过该轮。普通工具与正文工具一起可用时要求模型选择工具；正文工具与真实工具混用的异常回复会停止真实工具执行。正文工具本身不会执行外部动作，也不会额外生成一次回复。

若接口返回“不支持 tools / tool_choice”等 HTTP 错误，不会悄悄改成普通模式重发。关闭扩展后可恢复原请求。原生 Gemini 通常一次返回完整函数参数，因此无法承诺与普通文本流一样逐字出现。

## 状态与限制

未完成、取消和普通兜底说明显示在对应消息下方，不写进正文，也不会混进下轮提示词。状态随消息和候选保存在 `extra.gemini_reply`；刷新、切换候选后可恢复。手动编辑过的正文会标为“已手动修改”。

`complete: true` 表示本次响应在协议层完整接收，不代表模型一定写完了故事，也不是语义质量判定。`mode: tools` 表示真实工具阶段，不能当最终正文收录。未来独立记忆插件如需读取，可要求 `complete === true` 且 `mode` 为 `tool` 或 `plain`；本插件不控制其他扩展的总结行为。酒馆仍按自己的流程发出消息事件。

扩展不额外发起续写，不提高输出长度上限，不禁用用户预设或原生推理，不加随机提示串。酒馆自身的自动续写、自动候选和用户正则仍按原设置运行。空回重试及新增工具说明可能增加用量；提示组装后新增的工具说明不会回算进酒馆界面显示的提示 Token 预算。

响应等待按每次接收数据的间隔计算，默认两分钟，不是整轮回复最多两分钟。关闭流式显示时，取消不会额外创建一条包含后台缓冲内容的消息。

接入使用发送前事件标记请求，并包装页面的 fetch。仅修改同源、准确路径、由本扩展标记的主聊天 POST；标记不会送到模型。因为当前酒馆没有正文工具响应转换接口，这是本版明确的兼容边界。其他扩展若再次替换 fetch 且不调用之前的实现，或修改请求类型/回复结构，需要另做联测。

## 停用、更新和回退

关闭开关即可让后续请求恢复原状；进行中的请求可用酒馆“中止请求”停止。完全移除时，停止生成，将本扩展文件夹移出 `third-party`，再刷新页面。历史正文保持可读；附加状态仍保存在聊天文件内，停用后不显示插件提示。

通过仓库安装的版本可使用酒馆扩展管理中的更新功能；手动安装的版本用新版本替换本扩展文件夹，然后刷新。回退时换回原文件夹；本版没有数据库迁移。
